# Backend: Spring Todolist API

The REST API of the todo list application. It manages **categories**, **tasks** and **users**, and authenticates clients with **JWT**.

This file is the developer guide for the `backend/` folder. For the full API reference, the access rules, the error format and the data model, see the [root README](../README.md).

## Quick start

### With Docker Compose (recommended)

From the project root:

```bash
cp .env.example .env      # then set APP_JWT_SECRET
docker compose up -d --build backend
```

Compose also starts the `db` service, and the backend waits until it is healthy. The API is then on <http://localhost:8080/api>.

### With Gradle

You need **JDK 21** and a PostgreSQL database. The Gradle Wrapper downloads Gradle itself.

```bash
cd backend
export SPRING_DATASOURCE_URL=jdbc:postgresql://localhost:5432/todolist
export SPRING_DATASOURCE_USERNAME=todolist
export SPRING_DATASOURCE_PASSWORD=todolist
./gradlew bootRun
```

Without `APP_JWT_SECRET`, the backend uses the development key from `application.properties` (see the warning below).

### Useful URLs

| URL                                           | What                                  |
|-----------------------------------------------|---------------------------------------|
| <http://localhost:8080/api>                   | API root                              |
| <http://localhost:8080/swagger-ui/index.html> | Swagger UI, to try every endpoint     |
| <http://localhost:8080/v3/api-docs>           | OpenAPI 3 specification (JSON)        |

To call a protected endpoint from Swagger UI, log in with `POST /api/auth/login`, copy the token, then click **Authorize**.

## Configuration

Configuration lives in [`src/main/resources/application.properties`](src/main/resources/application.properties). Spring maps every property to an environment variable: `app.jwt.secret` becomes `APP_JWT_SECRET`, and so on.

| Property                      | Environment variable           | Default              | Purpose                                     |
|-------------------------------|--------------------------------|----------------------|---------------------------------------------|
| `spring.datasource.url`       | `SPRING_DATASOURCE_URL`        | *(none)*             | JDBC URL of the database                    |
| `spring.datasource.username`  | `SPRING_DATASOURCE_USERNAME`   | *(none)*             | Database user                               |
| `spring.datasource.password`  | `SPRING_DATASOURCE_PASSWORD`   | *(none)*             | Database password                           |
| `spring.jpa.hibernate.ddl-auto` | `SPRING_JPA_HIBERNATE_DDL_AUTO` | `update`          | Hibernate creates and updates the schema    |
| `app.jwt.secret`              | `APP_JWT_SECRET`               | a development key    | Base64-encoded HMAC key for signing tokens  |
| `app.jwt.expiration-ms`       | `APP_JWT_EXPIRATION_MS`        | `86400000` (24 h)    | Token lifetime                              |
| `app.admin.username`          | `APP_ADMIN_USERNAME`           | *(empty: disabled)*  | Initial admin account, created at startup   |
| `app.admin.password`          | `APP_ADMIN_PASSWORD`           | *(empty)*            | Its password (at least 8 characters)        |
| `app.admin.email`             | `APP_ADMIN_EMAIL`              | *(empty)*            | Its email address                           |

> [!WARNING]
> The default `app.jwt.secret` is committed to the repository. It is for development only: anyone who knows it can forge tokens. Always set `APP_JWT_SECRET` outside development, for example with `openssl rand -base64 64`. `compose.yaml` refuses to start without it.

### The initial admin account

Accounts created through the API always get `ROLE_USER` only. To get a first admin, set the three `APP_ADMIN_*` variables. At startup, [`AdminAccountInitializer`](src/main/java/com/example/spring_todolist/config/AdminAccountInitializer.java):

- does nothing if the username is empty;
- validates the values with the same rules as registration, and stops startup with a clear error if they are invalid;
- creates the account with `ROLE_USER` and `ROLE_ADMIN` if the username does not exist yet;
- never changes an existing account. Otherwise, whoever registered that username first would become an admin.

## Architecture

```
HTTP request
   │
   ▼
JwtAuthenticationFilter ── reads "Authorization: Bearer …", fills the SecurityContext
   │
   ▼
Controller ── validates the DTO (@Valid), checks @PreAuthorize, picks the status code
   │
   ▼
Service ── business rules, @Transactional, throws business exceptions
   │      └── Mapper: entity ↔ DTO
   ▼
Repository ── Spring Data JPA
   │
   ▼
PostgreSQL
```

Each layer has one job:

- **Controllers** contain no business logic. They call one service method and return its result.
- **Services** are `@Transactional(readOnly = true)` at class level. Methods that write override it with `@Transactional`. They throw `ResourceNotFoundException`, `DuplicateResourceException` or `ResourceInUseException`, and never build HTTP responses.
- **Mappers** are Spring `@Component`s with no repository access. When a request holds a foreign key, such as `TaskRequest.categoryId`, the service resolves it, not the mapper.
- **Entities are never returned to clients.** Every response goes through a `*Response` record, so internal fields such as the password hash cannot leak.

### Business rules worth knowing

| Rule | Where |
|------|-------|
| Usernames and emails are unique (409 otherwise) | `UserService` |
| Passwords are hashed with BCrypt. The plain value goes through the transient `User.plainPassword` field and is cleared after hashing | `UserService` |
| New accounts get `ROLE_USER`, whoever creates them | `UserService` |
| `PUT /api/users/{id}` is a partial update: `null` fields are ignored | `UserService` + `UserMapper` |
| Only an admin may send `roles` in an update (403 otherwise) | `UserController` |
| A task's `categoryId` must point to an existing category (404 otherwise) | `TaskService` |
| A category used by at least one task cannot be deleted (409) | `CategoryService` + `TaskRepository.existsByCategoryId` |
| `Task.createdAt` is set by the server when the task is created | `Task` (`@PrePersist`) |

## Security

Configured in [`SecurityConfig`](src/main/java/com/example/spring_todolist/config/SecurityConfig.java):

- **Stateless**: no session, no cookie. CSRF, HTTP Basic and form login are disabled.
- **Public paths**: `/api/auth/**`, `/api/categories/**`, `/api/tasks/**`, Swagger UI, the OpenAPI spec and `/error`.
- **Everything else needs a valid token**, including all of `/api/users/**`.
- **Method security** (`@EnableMethodSecurity`) adds per-endpoint rules on `UserController`, for example `hasRole('ADMIN') or #id == authentication.principal.id`.

### How a token is checked

1. `JwtAuthenticationFilter` reads the `Authorization: Bearer <token>` header.
2. `JwtService` checks the signature and the expiry date.
3. `CustomUserDetailsService` loads the user from the database. The roles therefore come from the database, not from the token.
4. If the token is missing or invalid, or the user no longer exists, the filter leaves the request unauthenticated. It never fails by itself: the access rules then decide between letting the request through and returning 401.

`RestAuthenticationEntryPoint` (401) and `RestAccessDeniedHandler` (403) write the same `ApiError` JSON body as the rest of the API.

### Token content

```json
{ "sub": "jdupont", "roles": ["ROLE_USER"], "iat": 1762300000, "exp": 1762386400 }
```

The frontend reads `sub`, `roles` and `exp` to adapt its interface. It never trusts them for access control.

## Error handling

[`GlobalExceptionHandler`](src/main/java/com/example/spring_todolist/exception/GlobalExceptionHandler.java) turns exceptions into an `ApiError` body (`timestamp`, `status`, `message`):

| Exception                          | Status |
|------------------------------------|--------|
| `MethodArgumentNotValidException`  | 400. The message lists `field : error` pairs |
| `HttpMessageNotReadableException`  | 400. Generic message, so internal details stay hidden |
| `BadCredentialsException`          | 401. The same message for a wrong username or a wrong password |
| `ResourceNotFoundException`        | 404    |
| `DuplicateResourceException`       | 409    |
| `ResourceInUseException`           | 409    |

Messages are in French, without accents.

## Tests

The backend was written **test-first**. It has **175 tests**, which cover every branch of the code (measured with JaCoCo); only `main()` is not covered.

### Running them

```bash
cd backend
./gradlew test
```

The only requirement is a running **Docker** daemon. The test configuration ([`src/test/resources/application.properties`](src/test/resources/application.properties)) uses the Testcontainers JDBC URL `jdbc:tc:postgresql:17-alpine:///todolist`. It starts a throwaway PostgreSQL 17 container and removes it at the end. It does not publish a fixed port and never touches your development database.

Reports:

- HTML: `build/reports/tests/test/index.html`
- JUnit XML: `build/test-results/test/`

To run one class or one method:

```bash
./gradlew test --tests '*CategoryServiceTest'
./gradlew test --tests '*CategoryServiceTest.delete_*'
```

### Kinds of tests

| Package      | Style | What it checks |
|--------------|-------|----------------|
| `entity`     | Plain unit tests with a Jakarta `Validator` (`ValidationSupport`) | Bean Validation constraints, `@PrePersist` |
| `mapper`     | Plain unit tests | Every field of every conversion, `null` handling |
| `service`    | Mockito (`@ExtendWith(MockitoExtension.class)`) | Business rules, the exceptions thrown, what is saved |
| `repository` | `@DataJpaTest` + `@AutoConfigureTestDatabase(replace = NONE)`, on the real PostgreSQL container | Derived queries and database constraints |
| `controller` | Standalone `MockMvc` with the service mocked and `GlobalExceptionHandler` attached | Routes, status codes, JSON bodies, validation errors |
| `security`   | Unit tests, plus `@SpringBootTest(webEnvironment = RANDOM_PORT)` with `TestRestTemplate` | JWT, the filter, 401 and 403 bodies, and the access rules end to end |
| `config`     | Mockito | The initial admin: created, skipped, rejected |

Test names follow `method_condition_shouldResult`, for example `delete_whenCategoryStillHasTasks_shouldThrowResourceInUseException`.

The integration tests (`SecurityIntegrationTest`, `UserAuthorizationIntegrationTest`) go through real HTTP calls, so they cannot roll back their data. They generate unique usernames and emails on each run instead.

## Adding a new resource

To add an entity, for example `Tag`, follow the existing layers. Write each test before the code it covers:

1. **Entity** in `entity/`: JPA annotations, Lombok (`@Getter`, `@Setter`, `@Builder`…), Bean Validation constraints. Add `TagTest`.
2. **Repository** in `repository/`: `interface TagRepository extends JpaRepository<Tag, Integer>`. Add a `@DataJpaTest` for any derived query.
3. **DTOs** in `dto/`: a `TagRequest` record with its constraints and `@Schema`, and a `TagResponse` record.
4. **Mapper** in `mapper/`: `toEntity`, `updateEntity`, `toResponse`, `toResponseList`. Add `TagMapperTest`.
5. **Service** in `service/`: business rules, `@Transactional`, `ResourceNotFoundException` for unknown ids. Add `TagServiceTest` with Mockito.
6. **Controller** in `controller/`: routes, `@Valid`, `@ResponseStatus(CREATED)` and `NO_CONTENT`, `@Tag`, `@Operation` and `@ApiResponses`. Add `TagControllerTest` with standalone MockMvc.
7. **Security**: in `SecurityConfig`, decide whether the paths are public. If not, add `@PreAuthorize` rules and an integration test.
8. Update the frontend models (`frontend/src/app/core/models.ts`) and the [root README](../README.md).

## Docker image

The [`Dockerfile`](Dockerfile) has two stages:

1. **`gradle:9.8.1-jdk21`**: downloads the dependencies in their own layer, builds the jar with `bootJar -x test`, then splits it into layers with `java -Djarmode=tools … extract --layers`. The Gradle cache uses a BuildKit cache mount.
2. **`eclipse-temurin:21-jre-alpine`**: copies the layers from the least to the most frequently changed (dependencies, loader, snapshot dependencies, application). It runs as the non-root user `spring`, on port 8080.

`JAVA_OPTS` defaults to `-XX:MaxRAMPercentage=75 -XX:+UseContainerSupport`, so the heap follows the container's memory limit.

To build it alone:

```bash
docker build -t spring-todolist-backend backend
```

In `compose.yaml`, the `backend` service has a health check on `GET /api/categories`. The `frontend` service waits until it passes.

## Conventions

- **Constructor injection** with Lombok `@RequiredArgsConstructor` and `private final` fields. There is no `@Autowired` on fields in the main code.
- **DTOs are records.** Entities stay inside the backend.
- **IDs are `Integer`.**
- **Comments, error messages and OpenAPI descriptions are in French, without accents**, like the commit messages.
- **Indentation**: 4 spaces in Java files, tabs in `build.gradle.kts`, as generated by Spring Initializr.
